# Primary sources and design implications

Reviewed 2026-10-14 by Jason Stys. References informed testable boundaries; this is not an assertion of certification or live-provider integration.

- [AWS policy evaluation](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html), [permissions boundaries](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_boundaries.html): explicit deny and ceilings matter, but resource/session principal and organization interactions prevent claiming our generic policy is a complete AWS IAM evaluator.
- [GitHub OIDC in AWS](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws): exact aud/sub trust and repository/branch/environment context matter. Newer repository subject formats include immutable owner/repository IDs. The HCL module intentionally supports the immutable branch profile only; it does not guess a real repository's token profile or use wildcard trust.
- [PyJWT API](https://pyjwt.readthedocs.io/en/stable/api.html): algorithms must be fixed independently of attacker-controlled headers. Signature/issuer/audience verification uses the library; explicit trusted-clock time checks replace wall-clock temporal validation for deterministic tests.
- [cryptography Ed25519](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/): use established key generation/signatures; no homemade cryptographic algorithm or persisted fixture signing keys.
- [OPA policy language](https://www.openpolicyagent.org/docs/policy-language), [OPA errors](https://www.openpolicyagent.org/docs/errors): native strict compilation and strict built-in errors distinguish malformed engine execution from a policy denial. Rego declaratively expresses the trusted registry/resource constraints.
- [Terraform tests](https://developer.hashicorp.com/terraform/language/tests): tests default to apply unless overridden; every test here explicitly uses plan, with no provider/resource/backend. This checks logical document construction without remote side effects.
- [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions): current artifact bytes, accrued included billing usage and separate cache bytes are distinct; no new artifact/cache upload is required for this evidence-driven lab.

Languages play distinct roles: Python integration/crypto/error/evidence; Rego native policy-as-code; HCL validated infrastructure document expressions; TypeScript runtime browser contracts and accessible DOM; HTML/CSS semantics/layout; Bash orchestration. Closed schemas, descriptive names, checked symbol maps, bounded parsing/state and focused contracts support self-documentation and maintainability. Complexity/timing limits are documented rather than equating Big-O with production speed.

## Native maintenance review — 2026-11-10

The [official OPA1.22.3 release](https://github.com/open-policy-agent/opa/releases/tag/v1.22.3) supplies immutable platform assets. Native packaging verifies provider digests and upstream checksum sidecars, retains actual linked-module/runtime notices, and uses only the existing fixed local JSON/Rego route. [OPA comprehensions](https://www.openpolicyagent.org/docs/policy-language#comprehensions) support the authored indexed batch; they do not authorize arbitrary caller queries. The [native validation report](reports/native-workbench-2026-11-10.md) records actual Go/module versions and residual HTML-advisory scope rather than equating a version upgrade or npm/Python audit with full binary reachability clearance.
